# Memorive 总体设计

*面向使用者和贡献者的设计说明 · v1.03 · 2026 年 10 月*

Memorive 把资料处理、研究问答、引用核对和知识复用连成一条流程。这份文档介绍数据怎样流动、各个模块负责什么、出错时怎样处理，帮助你理解 Memorive 如何形成可以回查的研究记录。字段定义、提示词、阈值和测试记录保存在各模块的契约和运行记录里，这里只讲设计思路。

## 设计原则

**研究者做最终判断。** AI 负责理解、整理、分析、推荐和提醒；导入、准入、知识回流和发布都由研究者确认，原始数据怎样处置也由研究者决定。自动执行的任务只在已经授权的范围内运行。

**资料比工具长久。** 原件、Markdown、文献卡片、笔记和决策记录长期保存，模型和软件可以随时更换。检索索引和界面显示都从这些资料生成，可以随时重建。

**按证据判断质量。** 格式正确、内容可信、抽取完整、来源可追溯是分别检查的几件事。关键数值、因果判断和准备写进论文的内容优先核对；普通的、可以单独处理的缺口会保留并标明，只有核心证据出错或继续输出会误导时才停下。

**保留原文和每个版本。** 资料始终以原语言保存，翻译只发生在显示层。修改会生成新版本，旧内容、审核记录和失败记录都会保留。

**按需逐步建设。** 先完成最小的研究闭环，再补充质量管理、版本管理和研究运营。每项新功能都有清楚的职责和依赖。

## 整体架构

Memorive 有四条主要流程：

- **资料处理**：导入资料 → 文档处理 → 证据提取生成文献卡片 → 证据审核 → 知识准入 → 进入正常检索。
- **研究问答**：提出问题 → 证据检索组装上下文包 → 研究分析生成回答 → 必要时独立审核 → 由你判断。
- **知识复用**：从已准入的资料中发现研究机会；你选定的结论经知识回流成为候选，确认后进入知识库。
- **外部发现**：文献发现按你设定的方向获取题录，研究推荐整理候选。题录和链接可以自动存进资料库，全文由你补充，之后再走正常的处理和准入流程。

原件和处理过程中的中间结果随时可以保存；进入正常检索和分析的资料需要先通过准入。研究报告、数据与逻辑核查、应用更新与维护是这几条流程旁边的辅助模块。

### 模块分工

| 分组 | 模块 | 负责什么 |
| --- | --- | --- |
| 处理与分析 | 文档处理、证据提取、证据检索、研究分析 | 从原始资料得到可以引用的证据和分析回答 |
| 共用服务 | 证据审核、检索权重、知识准入、模型服务 | 内容审核、检索排序、准入状态和模型调用 |
| 核查 | 数据与逻辑核查、质量评估 | 检查数值和逻辑，持续评估整体质量 |
| 记录与复用 | 知识回流、运行记录、决策记录、版本与谱系 | 管理回流候选，记录运行过程、决策理由和版本关系 |
| 研究运营 | 研究机会、研究报告、文献发现、研究推荐 | 找出分歧和缺口，汇报变化，发现并推荐新文献 |
| 桌面应用 | 应用层、任务运行、应用更新与维护 | 连接界面和业务模块，运行任务，管理安装和更新 |

每个模块只做自己的事：文档处理负责转换和 OCR 质量；证据提取负责抽取和结构检查；研究分析检查引用是否来自本次材料；证据审核判断证据能否支持主张；知识准入只根据请求和依据改变状态。技术重试由模型服务和任务运行器处理，内容返修由证据提取和证据审核处理，运行记录只负责记录。

## 数据如何保存

### 两层资料

**来源层**保存原件和可以回溯的文本：PDF 或其他原始文件，以及转换得到的 RawMD、清理后的 CleanMD 和切分好的片段（Chunks）。原件是最终依据，转换结果保留来源位置和转换记录。

**卡片层**保存文献卡片（Card），每张卡片忠实提炼一篇文献，用于检索、比较和回查。个人批注、跨篇总结、分析报告和回流内容是另外的派生产物，和卡片分开保存。

向量索引、字段向量和桌面资料库属于**访问层**：它们指向具体的来源和版本，可以随时重建。

### 身份、来源与语言

每篇文献有稳定的 paper_id。保存下来的每个产物都记录 ID、内容 hash、schema 版本、来源范围、父版本、运行批次和执行配置；跨多篇文献的上下文包和分析可以有多个父产物。

卡片里的重要信息同时保存提炼结果和来源锚点（片段 ID 加原文引句）。引句必须能在对应的原文片段中找到；提炼的意思是否准确，再由审核判断。历史资料缺少的身份或来源信息标为未知，Memorive 不会靠文件名或相似文本去推测。

原文、文本和卡片保持来源语言。界面、系统消息以及新生成的问答、建议和报告按你选择的内容语言输出；原文、引用、题录和历史版本保持原样。语言在任务开始时确定，缓存也按语言分开。

### 比较上下文

跨文献比较时，Memorive 用一组通用字段描述每项结论的条件：

| 字段 | 含义 |
| --- | --- |
| Research Object | 研究对象、材料、样本、文本或系统 |
| Intervention / Factor | 考察的因素或干预 |
| Comparator | 对照对象或比较基准 |
| Method | 方法、研究设计或分析框架 |
| Metric | 评价指标及其含义 |
| Boundary Condition | 结论成立的条件和边界 |
| Scale / Context | 尺度、场景和应用背景 |
| Claim Type | 结论类型：因果、相关、机制、性能、方法验证等 |

不同学科只替换字段的别名。证据提取负责抽取这些字段，研究机会用它们判断两项结论是否可比。

## 资料处理

### 文档处理

![图 2 · 文档处理](assets/figure-02.svg)

*图 2 · 文档处理*

文档处理把原始文档、图片或笔记变成原件存档、RawMD、CleanMD、片段和向量索引，并记录每一步的转换情况。

| 步骤 | 做什么 |
| --- | --- |
| 导入 | 保存原件、来源、身份、时间和数据处置权标记 |
| 转换 | 把 PDF 等文件转成 RawMD，有问题的页面按需 OCR，生成转换报告 |
| 清理 | 用本地规则去掉页眉页脚、多余断行、串栏等排版噪音 |
| 切分 | 按章节、段落、表格、图注切分，生成稳定的片段 ID |
| 向量化 | 用选定的模型生成向量，记录模型和时间 |

解析结果保留段落、表格、上下标以及页码和行号锚点。也可以选用本地 Marker 解析。

**按页 OCR。** 普通的数字 PDF 直接本地解析。只有扫描页、几乎没有文字、乱码或结构损坏的页面才做 OCR：先本地诊断、检查数据处置权，再交给选定的 OCR 模型，和原解析结果并排核对后合并。某一页失败时，其他页面照常保留，缺失的页面会标出来。

**笔记核对。** 笔记转换后默认暂停，由你检查转录和格式，确认后再继续。

**重建向量。** 模型名称相同，向量空间也可能不同，所以复用旧索引前要核对维度、归一化方式和距离度量。重新向量化时，先确认新文本可以生成，再保存旧向量的快照，清理后重建；中途停止就从快照恢复。

目前支持 14 种文件格式，其中 JPEG、PNG、TIFF 只做基本的图像检查，这一步不提取图中文字。旧版 Office 文件借助本机的 Office 转换，转换时禁用宏和链接更新。

### 证据提取与文献卡片

![图 3 · 证据提取](assets/figure-03.svg)

*图 3 · 证据提取*

证据提取读取一篇文献的 CleanMD 和片段，生成文献卡片、辅助抽取结果和覆盖记录。卡片先经过本地检查，再交给证据审核和知识准入。

卡片的核心字段包括研究问题、对象、方法、关键结果、作者结论、适用条件和来源锚点；辅助抽取包括关键数据、比较上下文、作者自述的局限和展望，以及可选的术语和引用关系。研究本身的局限和结论的适用边界分开记录；个人想法、评论、假设和跨篇综合放在卡片之外。

| 规则 | 提炼要求 |
| --- | --- |
| R1–R2 | 保持作者主张的强度；多步过程和多组比较完整保留 |
| R3–R4 | 数值连同统计类型、阶段、样本和范围一起提取；指标写明作用范围、分母和对照 |
| R5–R6 | 结论附上真实的适用条件；区分研究对象和用来表征、测试的样品 |
| R7–R8 | 术语按作者的定义；来源锚点覆盖实际取材的位置 |
| R9 | 原文给出的信息都要提取，原文确实没有的就标明。明显笔误按上下文处理时，保留原值、依据和修改痕迹 |

**覆盖状态。** 每个必填项标为原文有、原文没有、不适用、抽取遗漏或未评估中的一种。“没找到”和“原文没有”分开记录。

**生成与修复。** 写出卡片前，检查 schema、类型、来源 ID、锚点和字段之间的约束，重要的引句要和原文逐字比对。审核发现可修复的问题时，一张卡片集中修复一次，只改有问题的字段；遇到系统性失败，就重新建立卡片和运行记录，前一次的失败结果保留。

**长文。** 篇幅很长的文献会分片提取、逐层合并，整份结果写完后才对外可见。

## 检索与问答

### 证据检索

![图 4 · 证据检索](assets/figure-04.svg)

*图 4 · 证据检索*

证据检索根据问题、可用资料和权重设置，组装一个带来源、有长度上限的上下文包（Context Pack）。它分三步：理解问题、召回候选、打包上下文。先用卡片和字段信号定位，需要时再深入原文；卡片锚点只是线索，真正交给模型的证据文本来自原文片段。

打包时同时考虑 token 上限、来源多样性、问题的各个方面和有价值的反例。同一章节里的表格与标题、脚注，以及紧邻的连续段落，可以作为一组一起提供。上下文包会记录覆盖到和没覆盖到的问题方面，并带上每份资料的数据处置权限制，一路传给分析和审核。

### 检索权重

![图 5 · 检索权重](assets/figure-08.svg)

*图 5 · 检索权重*

| 分组 | 权重 | 含义 |
| --- | --- | --- |
| 相关性 | SimilarityWeight | 和当前问题的向量相似度 |
| 相关性 | SemanticWeight | 按问题的各个维度计算的字段相关性 |
| 权威与个人价值 | ManualWeight | 你写明理由后设定的重要程度 |
| 权威与个人价值 | RuleWeight | 年份、期刊、被引次数、文献类型等信号 |
| 权威与个人价值 | NoteWeight | 你的笔记、批注等研究痕迹 |
| 权威与个人价值 | CitationWeight | 这份资料在你的研究中被引用的次数和用途 |

最终得分 = 相关性加权和 + 衍生系数 × 权威加权和。各项系数可以按研究目的调整。

**衍生内容降权。** 跨篇总结、概念关系和个人批注这类衍生内容只降低权威分，相关性照常计算；跨篇总结降得最多，个人批注最少。这样可以避免二手总结挤掉它所依据的原始文献。卡片的字段向量只为已准入的卡片生成，和原文向量分开存放。

### 研究分析

![图 6 · 研究分析](assets/figure-05.svg)

*图 6 · 研究分析*

研究分析根据问题和上下文包生成回答，回答分四部分：文献支持的内容及引用、本库文献之外的 AI 补充、风险与不确定性、建议回查的原文位置。资料覆盖不足时，会减少 AI 补充，并分别说明研究本身的局限、来源之间的不一致和检索遗漏。

研究分析会检查每条引用是否来自本次上下文包：不合规的引用移出文献支持部分并说明原因，其余内容保留。证据是否充分、主张有没有说过头，交给证据审核独立判断。回答提供观点、证据和分析结构，最终结论由你来形成。

**回答版本。** 每次回答都记录所用的来源、条件和风格设置。重新生成会形成新的回答分支，旧分支保留，但不会混进新的上下文；复制、切换版本和恢复草稿都不调用模型。30 天未打开或超过 100 条消息的对话会自动归档，置顶和正在使用的对话除外。

### 研究 Skill

memo-research Skill 让 Codex、Claude Code 等 Agent 帮你读文献：先读完并形成回答，再集中核对支撑关键主张的原文，没有依据的说法会修改或标为不确定。

单独使用时，Skill 会为每篇文献保留原件、RawMD 和 source.json。在研究问答里通过附件入口选择 source.json，Memorive 核对文件后直接复用，省去重新转换。你也可以从当前对话导出交接包，交给 Agent 继续读；它的回答通过同一对话的附件入口返回，并和当前问题、资料版本关联。返回的回答需要你确认后才进入知识库。

## 审核与核查

### 证据审核

![图 7 · 证据审核](assets/figure-07.svg)

*图 7 · 证据审核*

证据审核检查卡片或分析中的每项主张有没有证据支持。卡片和分析各自使用独立的审核模型，审核模型和生成模型来自不同的模型家族。

**卡片审核。** 先做一次完整审核，没有问题就结束；发现可修复的问题时集中修复一次，再只对改动的部分复审，最后做一次整体检查。只有明确、唯一、可以单独分离的错误内容才会被删除，删除的内容留档；有歧义的交给你处理。全部处理完的卡片标为“完成”；省略了部分内容但仍然可用的，标为“带遗漏通过”；核心问题没解决的保持失败，或等待你决定。

**分析审核。** 按风险决定是否审核以及审核哪些部分，跳过时记录理由。审核模型只看到主张和引用的证据，看不到生成时的推理过程。

### 数据与逻辑核查

数据与逻辑核查检查文献文本和表格里的数值关系与内部逻辑，报告中标出原文位置、依据、适用条件和覆盖范围。

确定性检查先弄清百分数、比例、单位和统计含义，再检查明确的等式、范围和数值关系；条件不足或无法比较时，标为待核或覆盖受限，Memorive 不会去猜分母或分组。模型逻辑核查用来提出有原文依据的疑点。规则结果、模型疑点和你的意见分别保存，模型提出的怀疑在你确认之前只算疑点。

核查只出报告，原文保持原样，也不推断作者意图。它和证据审核分工不同：前者看数据和逻辑本身，后者看证据能否支持提炼出的主张，两种结论分别保存。

### 质量评估

![图 8 · 质量评估](assets/figure-15.svg)

*图 8 · 质量评估*

质量评估通过随机抽检、按风险抽检和固定基准测试持续监测质量。权重高、常被引用、准备写进论文或审核时有过分歧的内容优先抽检；更换模型、提示词或规则后，用对应的测试包重新检查。

| 质量维度 | 检查什么 |
| --- | --- |
| 文字忠实 | 文字、数值、单位和引文是否忠于来源 |
| 证据覆盖 | 证据是否覆盖主张的条件、范围和比较对象 |
| 跨产物一致 | 卡片、上下文包、分析、审核和发布内容之间是否一致 |
| 科学合理 | 统计口径、单位、样本、时间和数量级是否合理 |
| 版本新鲜 | 依据的上游版本是否兼容、是否过时 |

五个维度分别记录结果，未评估的维度单独显示。比较数值前，先对齐指标、单位、条件、统计类型、时间、样本和对照，对不齐的标为“不可直接比较”。OCR 结果区分正文、封面、目录、页眉页脚和参考文献，以免把正文以外的数字当成研究结果。

基准测试按任务角色维护，每个版本都固定完整的题目、标准答案、评分器和清单，并在不同模型之间复用；标准答案只在本地评分时使用，受测模型看不到。

## 知识与记录

### 知识准入

![图 9 · 知识准入](assets/figure-09.svg)

*图 9 · 知识准入*

卡片有三种准入状态：待定（pending）、已准入（active）和隔离（quarantined）。待定的卡片可以查看和审核；进入正常检索、研究机会分析和自动反馈的，只有已准入的卡片。

知识准入只根据明确的请求和依据改变状态，每次变更生成一条不可修改的事件，由运行记录保存、由版本与谱系关联。判断质量、重试和修复都由其他模块负责。

### 知识回流

![图 10 · 知识回流](assets/figure-11.svg)

*图 10 · 知识回流*

可以回流的内容包括批注、判断、假设、稳定的概念关系和跨文献综合。你的原始记录可以自动保存，也可以自动整理成候选；进入知识库之前都要经过你确认。

流程是：选定内容 → 生成带来源和理由的候选 → 检查可以放到哪里、会改动什么 → 你选择接受、修改、拒绝或暂缓 → 必要的审核和准入 → 保存版本。确认过的总结仍然是二手内容，会按衍生内容降权，权威性低于原始文献。

### 版本与谱系

![图 11 · 版本与谱系](assets/figure-14.svg)

*图 11 · 版本与谱系*

每个产物都有不可变的 ID、内容 hash、类型、运行批次、来源范围、创建时间，以及一个或多个父产物。修改原件、文本、卡片、反馈或决策时，都会生成新版本，原来的版本保留。

| 生命周期 | 含义 |
| --- | --- |
| 使用热度：活跃 / 冷 / 归档 | 影响检索优先级，和删除无关 |
| 版本：当前 / 已替代 / 历史 | 记录版本替换和历史 |
| 派生对象：草稿 / 当前 / 已替代 / 历史 | 批注、总结等派生内容的版本状态 |

Memorive 根据精确的父版本、schema 和来源范围判断一个产物是否仍然兼容；父版本缺失时标为“来源未知”。卡片更新后，用旧卡片写成的分析会提示可能过时。

### 运行记录与决策记录

![图 12 · 运行记录](assets/figure-12.svg)

*图 12 · 运行记录*

运行记录保存各模块和任务的事件：给你看的是进度和错误，供排查用的是模块、对象、阶段、原因和证据位置。它只负责记录，判断和修复由其他模块完成。

| 记录 | 内容 |
| --- | --- |
| 尝试记录 | 每次实际调用的结果、路线和证据 |
| 文献结果记录 | 每篇文献在每次运行中的最终结果；重做时另起一次运行 |
| 发布记录 | 发布请求、选中的内容、结果和回执 |

之后的成功会追加新记录，之前的失败记录保留。外部调用在发送前记录请求身份、路线、权限和预算，返回后补上实际返回的模型、用量、费用和延迟；旧数据里缺失的字段标为未知。

![图 13 · 决策记录](assets/figure-13.svg)

*图 13 · 决策记录*

决策记录保存重要选择的背景、备选方案、最终选择、放弃的理由、影响范围和复查日期，例如模型准入、回滚、重新向量化、发布和撤回。运行记录说明发生了什么，决策记录说明为什么这样选。决定有变化时新建一条记录，原来的决定和理由保留。

### 研究报告

![图 14 · 研究报告](assets/figure-16.svg)

*图 14 · 研究报告*

研究报告从运行记录、准入和版本变化中整理研究事件，生成日报、周报和月报。日报关注新增、修改、待审和失败；周报关注重要进展、新文献、未完成的审核和潜在分歧；月报关注结构变化和长期待办。报告只汇报变化、风险和待办，准入状态保持原样。首页的 AI 近况和研究报告是两个功能，各自使用不同的资料范围。

## 研究机会与文献发现

### 研究机会

![图 15 · 研究机会](assets/figure-06.svg)

*图 15 · 研究机会*

研究机会从已准入的卡片中找两类线索：

- **分歧**：比较对象、条件、方法、指标、统计口径和时间范围后，找出条件可比但结论不同的地方。
- **缺口**：归纳作者明确写出的局限、空白和未来工作，保留原句和来源，并标出后来的文献是否已经填补。

结果分为四类：A 高度可比的分歧，B 条件或方法不同，C 表述、指标或结论类型不同，D 你确认忽略的。资料覆盖不足时，标为“不可比较”或“覆盖有限”。分析按主题增量进行，可以定时运行、手动触发，也可以在相关资料变化后运行；是否可比、有没有研究价值，由你判断。

### 文献发现

![图 16 · 文献发现](assets/figure-17.svg)

*图 16 · 文献发现*

文献发现根据主题、关键词、作者、期刊或引用链，从 arXiv 和 Crossref 获取带来源和推荐理由的候选文献。DOI、arXiv ID 或 PMID 完全一致且没有冲突时自动去重；只靠题名、作者匹配或标识有冲突的，交给你复核。同一研究的预印本、会议版、接收稿和正式版作为不同版本分别保留。

每篇候选从发表时间、首次发现时间、是否已在资料库中、与研究方向的关系四个角度标注新颖性，无法判断的标为未知。

首页提供“最新”和“相关”两个入口。按你的接收设置，题录和链接可以自动存进资料库，全文由你补充。候选要经过两次确认：第一次只生成待审的候选卡片，第二次才正式加入资料库。

### 研究推荐

![图 17 · 研究推荐](assets/figure-18.svg)

*图 17 · 研究推荐*

研究推荐在文献发现的基础上，按五个通道组织一组数量有限的推荐：核心、相邻、桥接、远景和覆盖补充。每个通道单独说明推荐理由，各通道的得分分开显示。

你查看、忽略的推荐和再次出现的推荐都会记录下来。忽略只作用于对应的文献和研究方向；反复出现的信号只会生成待你确认的策略建议。研究推荐负责发现和推荐，导入、提高权重和调整策略都由你决定。

## 模型服务与费用

![图 18 · 模型服务](assets/figure-10.svg)

*图 18 · 模型服务*

### 角色和执行通道

业务模块按角色请求模型，例如向量化、卡片提炼、卡片审核、分析、分析审核、机会分析、报告整理、页面 OCR 和重排。每次运行开始时，模型服务固定这次使用的供应商、模型、提示词、参数、执行位置、权限、预算和回滚目标。更换模型只需要改配置，业务逻辑保持不变。

执行过程是：角色请求 → 编译工作包 → 选择通道 → 独立的任务运行器 → API、命令行工具或本地模型 → 结果和每次调用的记录。任务运行器管理进程、超时、心跳、取消和恢复。目前内置七种命令行工具的接入，也可以自定义命令行工具的入口、参数和输入输出规则。

### 配置与故障处理

每个模型配置有两组状态：运行可用性（未知、可用、降级、缺失）和启用状态（候选、已批准、启用、弃用、隔离、退役）。质量评估提供各个角色的测试结果，由你或你批准的规则决定启用哪个模型。

每次调用都记录请求的模型和实际返回的模型，正式审核中两者对不上时会停下；同一批任务中途也不会悄悄换模型。调用前会检查网络出口所在地区是否符合服务商的地区政策，不符合或无法确认时不发送请求。网络波动和限流会在预算内自动重试；凭据、额度、服务下线或配置有问题时，只暂停受影响的环节，并说明原因和处理办法。超时后也不会自动改用付费服务。

### 费用与用量

每次调用分别记录三件事：通过什么方式调用（API、命令行或本地）、在哪里推理、怎样计费。经由命令行发出的 API 请求仍按 API 计费；在本机运行的程序也可能使用云端推理。订阅制命令行工具单次调用的金额可能无从得知，这时记为“未知”，不会算作零或免费。

费用分实际、估算、未知和冲突四类，按币种显示。它只覆盖 Memorive 记录到的调用，实际支出以服务商账单为准。用量记录缓存命中与未命中的输入、总输出、推理部分和可见输出；推理 token 本身包含在输出里，不重复相加。

### 输入缓存与会话续接

为了让服务商有机会复用输入的计算结果，固定的规则和资料放在前面，变化的任务放在后面。每个任务仍然单独请求，并完整检查结果；审核结论每次重新得出。服务商是否支持缓存，按 API、模型和实际通道分别识别，未知时就按不支持处理。

使用 Codex 时，Memorive 按精确的会话 ID 续接会话；身份不一致、已经过期或上次失败时，就新开一个会话。

## 桌面应用

### 技术结构

Windows 版使用 pywebview、PyInstaller 和 Edge WebView2 构建。界面通过应用服务调用 Python 业务层：界面 → IPC 命令和事件 → 应用服务 → 业务模块。作业、视图和恢复所需的状态保存在本地，断开或重启后重新生成显示内容。界面只通过应用服务操作数据；资料库显示的是原始来源、产物和版本关系。

### 主要界面

| 界面 | 做什么 |
| --- | --- |
| 设置 | 界面语言、模型档位、Thinking、凭据和能力状态；验证通过后才保存，失败时恢复原值 |
| 收件箱与当前任务 | 导入、去重、处理冲突和分派任务；可以暂停、取消、恢复、重试或改用其他配置 |
| 消息与工作日志 | 区分已读和已处理；可以跳到对应的任务、步骤和产物 |
| 资料库与会话库 | 查看来源和生成的内容；采集历史会话和加入知识库分开授权 |
| 模型考试与费用 | 按角色、测试版本和时间显示模型资格；费用按来源类型显示 |
| 文献发现与研究报告 | 推荐经两次确认后入库；报告汇报变化 |

界面分别显示运行状态、文献结果、审核依据、字段可信度、覆盖情况和版本关系。“带遗漏通过”的结果会列出可用的内容和删除原因。安全模式以只读方式运行核心功能，不加载自定义代码。

### 处理流程

桌面上的文献处理分九个步骤：

| 步骤 | 内容 |
| --- | --- |
| 01 文档导入 | 转换、清理、切分并记录来源 |
| 02 原文向量化 | 确定本次使用的向量空间 |
| 03 生成卡片 | 证据提取和本地检查 |
| 04 核对卡片 | 按审核规则执行 |
| 05 卡片准入 | 根据审核依据确定准入状态 |
| 06 整理分析材料 | 在 02 的向量空间里检索，按 07 的预算打包 |
| 07 生成分析 | 研究分析 |
| 08 核对分析 | 独立审核，或记录跳过的理由 |
| 09 人工判断 | 展示证据、异议和遗漏，由你决定 |

进度根据各步骤的实际事件和可计量的工作量计算。长任务支持断点续跑和心跳，同时保留取消、费用和重试上限。重排目前没有启用，检索结果按向量距离排序。

分析的审核修订流程是：生成 → 抽样独立审核 → 针对问题修订一次 → 独立复审改动的部分 → 通过，或删除仍有异议的内容 → 你最终审阅。问题的每个方面至少保留一条文献支持；原文、修订、来源、异议和删除记录都会保留。

### 会话管理与精炼

会话管理可以按来源筛选、搜索和分页浏览 Codex、Claude Code、本机文件和浏览器采集的对话，每条记录保留来源、同步时间和首尾消息。首次全量采集和之后的增量采集分别显示范围和完成状态；精炼结果作为新的产物保存，原对话保持不变。[R3][R4]

浏览器采集时由你选择 Edge、Chrome 或 Brave，只通过官方导出、公开 API、已登录页面上可见的内容或本机命令行工具的会话目录读取，Cookie 和浏览器存储不会被读取。采集后可以去重并精炼，生成 11 类候选内容，供你放到 5 类位置；每一项都可以接受、修改、拒绝或暂缓。对话内容只作为研究记录，加入知识库仍要经过相应的审核。

### 模型排行榜

排行榜展示模型、供应商、能力指标、输入输出价格、币种、来源日期和刷新状态，供选择模型时参考。排序和筛选会保留当前条件；来源不可用时显示失败状态。公开榜单只反映它覆盖的任务和时间范围，模型是否适合你的研究，还要用自己的资料测试。[R1][R2]

| 项目 | 显示方式 |
| --- | --- |
| 能力 | 标明基准、分数和日期，不同基准分开显示 |
| 价格 | 每百万输入和输出 token 的价格及币种，作为参考 |
| 状态 | 刷新时间、来源失败和缺失项，未知的保持未知 |

### 计费与用量面板

底部的“计费与用量”面板可以展开和收起。工具栏可以选择全部记录或本任务、近 7 天、近 30 天或本月，以及具体模型；主体在费用（含估算）、请求次数和 Tokens 之间切换，图表随筛选更新。本任务的费用归属不完整时，“本任务”选项不可选。费用分列实际和估算，请求次数包括失败和重试，Tokens 分列输入和输出。[R5]

## 隐私、存储与更新

### 数据处置权

数据归属和敏感程度分开记录。卡片目前区分自有（self）和受托（entrusted）两类：自有内容按你的配置使用；受托、无权处置或归属不明的数据默认只在本地处理，没有本地能力时就暂停相应的调用。

数据交给模型之前，都会先检查处置权，包括 OCR、向量化、提炼、分析、审核和命令行工具；上下文包在组合和传递时也带着这些限制。会话采集、交给模型精炼和正式加入知识库分别授权。

### 存储与凭据

程序目录保存应用本身，你选择的数据目录保存资料、会话、状态和生成的产物。原件、文本、卡片、分析和它们之间的版本关系是需要长期保留的资产，检索索引可以从它们重建。备份时同时保留内容和版本关系，恢复前先确认备份可以读取。

凭据交给本机的凭据存储管理，配置里只保存引用；日志、文档和导出内容里都没有 Key、登录令牌或浏览器 Cookie。导入旧设置时保留有效的本机引用，凭据本身留在原处。

### 更新与卸载

检查更新、下载和安装是三个独立的步骤。自动检查只获取正式版本的信息，检查失败时会如实提示。你确认版本、说明和大小后才开始下载。增量包必须对应当前安装的版本，组装结果要和完整包一致；版本对不上时，确认后可以改用完整包；签名或来源校验失败就停止。

下载并校验后，选择“退出后更新”：独立的更新助手会等 Memorive 完成任务、保存并正常退出后再安装，不会强行结束程序。更新完成后重新打开，确认版本、资料位置和设置。程序、配置和研究资料分别处理，更新前保留恢复条件；新版本开始写入数据后，旧备份就不再用来覆盖新内容。已有的审核结论在更新后保持原样。

安装、更新和卸载界面都提供中文、英文和日文。卸载时默认保留你的数据。
