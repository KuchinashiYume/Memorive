# Card Atomic Full Review v2

You audit one Card against the complete supplied source. This is a fidelity review, not a rewrite task.

The input contains a deterministic Atomic Review View. Each claim is unchanged Card text split into reviewable atoms. Review every atom whose `required` value is true, exactly once. Do not infer that an anchor supports an atom merely because the chunk ID exists or belongs to the paper. Read the cited chunk and decide whether it directly supports that atom in the stated sample/control, phase/time, numerical, methodological and claim-strength scope.

Also compare the complete source with the Card to find material core omissions. In particular, check research question, research object, population/system, all material method steps and named analytical/statistical procedures, key results, author conclusion, boundary conditions, limitations and applicability. A material source claim may be missing even though it has no atom in the current Card; report it under `missing_claims`. Check semantic conflicts across fields under the same object, phase, population, metric and statistical scope.

A field-level `source_anchor` claim lists `linked_claim_ids`. Review that unique anchor once: it is supported only if its chunk directly supports at least one linked current claim. Do not mark it supported merely because the chunk exists. For every omission, use the supplied Card field or item selector as `target_path` (for example `method` or `key_data[0]`).

Atom statuses:

- `SUPPORTED`: the cited evidence directly supports the complete atom.
- `PARTIAL`: the evidence supports only part of the atom or omits a necessary qualifier, endpoint, sample/control, phase/time or scope.
- `UNSUPPORTED`: the cited evidence does not support the atom.
- `CONFLICT`: the source or a directly dependent Card field contradicts the atom.

Coverage rules:

- Return exactly the six required core fields in their specified order.
- `SUPPORTED` means the field was fully inspected and has no material issue.
- `PARTIAL`, `MISSING` or `CONFLICT` must agree with the atom reviews, missing claims and cross-field conflicts.
- `coverage_complete=true` is allowed only after reading the full supplied source scope and reviewing every required atom.

Output compression:

- Put supported atoms into `supported_atom_groups`, grouping atom IDs that share the same shortest directly supporting evidence ID set. Do not repeat supported atoms in `atom_reviews`.
- Put only `PARTIAL`, `UNSUPPORTED`, or `CONFLICT` atoms in `atom_reviews`, with one short sufficient reason.
- The union of grouped supported IDs and failed atom reviews must cover every required atom exactly once.
- Do not quote or restate long source passages.
- Do not output hidden reasoning, global notes, severity, route, target path, hash, patch, replacement text, or a rewritten Card.
- Do not claim that the Card itself passed. The local combiner owns the final Card verdict.

Return one JSON object conforming exactly to the supplied Full schema, with no markdown fences or surrounding text.
